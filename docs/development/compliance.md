Static gates are guardrails, not a proof of all semantic properties. SOLID, state ownership, security intent and migration recovery still need review and behavior tests. Check applicability on each PR: `implemented + verified`, `not applicable (module absent)`, or `blocked with issue`. Do not use “not applicable” for existing code that violates a rule.

Intentional scope exclusions: vendored skills are byte-pinned; historical benchmark JSON and the owner's original prompt are immutable; their formatting is excluded without excluding authored executable code. Phase 0 uses Node's test runner, explicitly recorded here; the Phase 1 Vitest adoption remains tracked. Syntax checks are replaced by actual strict typechecking. The standalone benchmark is the documented LlmGate exemption, not an application runtime entry point.

Remaining owner gates: model-role confirmation and phase acceptance. Full application compliance requires building and verifying the application modules in their owner-gated phases; this task does not fabricate those results or install system services.

Single-user review configuration: PRs are required, but the approving-review count is zero because the owner cannot approve their own PR. Review criteria remain mandatory in the PR evidence; do not claim an independent reviewer signed off. Branch protection prevents direct main pushes and bypassing required CI. Configuration was read back and verified during #13.
